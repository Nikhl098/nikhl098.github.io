What is covered

  • GET, POST, PUT, PATCH, DELETE
  • Token login and requests with and without a token (403 checks)
  • Positive and negative cases, status codes, response body checks
  • Saving values between requests with collection variables: TC02 saves the token and TC04 saves the booking id

The bug

The one failing check (TC12) is a real defect: the API answers 500 instead of 400 when required fields are missing. It is written up in the repo’s bug report.

Run it yourself

Import the collection into Postman, open it and click Run. Expected: 28 of 29 checks pass.
